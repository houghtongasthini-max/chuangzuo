# AI拟真连续图片故事工作流 V4.0｜独立审查整合版

> 这是一套面向 **AI拟真连续图片故事** 的分阶段生产工作流。  
> 核心分工是：**主创AI负责写成，独立审查AI负责判断，挑战者AI负责建立单变量替代路线，创作者负责最终裁决。**

本README是一份可直接照做的操作手册，重点说明：

- 每个阶段由谁运行；
- 需要加载哪些文件；
- 需要输入什么；
- 模块会输出什么；
- 下一阶段具体复制哪一部分；
- 遇到RETURN、T2或视觉失败时怎样返回。

---

# 0｜第一次使用前先记住五条规则

## 规则1｜`00`必须伴随所有模块

每次运行01、02、03、04、05或T1—T3，都要同时加载：

```text
core/00-全局原则、证据与权限.md
```

`00`不是一个单独生产阶段，而是所有模块共同遵守的最高规则。

## 规则2｜每次只运行一个阶段

不要一次把01—05全部丢给AI，也不要要求模型“从选题直接做到发布文案”。

每次只加载：

```text
00
＋ 当前模块
＋ 上一阶段已经锁定的结果
＋ 当前问题直接需要的少量背景
```

## 规则3｜只复制`INPUT_TEMPLATE.md`中的当前提交块

`INPUT_TEMPLATE.md`是你的操作面板，不是要整份发送给AI的Prompt。

例如运行01时，只复制：

```text
A5｜直接复制给01的版本
```

运行02时，只复制：

```text
B2｜首次运行02的直接提交块
```

不要每次把整个INPUT_TEMPLATE发送给模型。

## 规则4｜02、03、T2必须隔离会话

推荐最低配置：

```text
会话A｜主创AI：01、02
会话B｜独立审查AI：03
会话C｜挑战者AI：T2，仅在触发时建立
会话D｜生产AI：04
会话E｜文案与复盘AI：05
```

它们可以使用同一种底层模型，但：

- 03不能在刚写完02的同一会话中运行；
- T2不能在刚完成03审查的同一会话中运行；
- 03不得读取02的创作过程和自我评价；
- T2不得读取03的完整审查过程，只读取正式门控结果。

## 规则5｜没有实际图片或真实数据，就不能运行对应审查

- 03模式B必须收到实际关键测试图；
- 04模式C必须收到实际完整成图；
- 05模式B必须收到真实后台数据、评论或明确的数据缺失说明。

不得用文字描述代替尚未生成的图片，也不得编造发布数据。

```text

  02-冠军故事骨架.md
  03-致命审查与关键视觉验证.md
  04-分镜、生图与定点QA.md
  05-发布文案与事实复盘.md

background/
  B1-市场与受众快照.md
  B2-现实素材与叙事资产库.md
  B3-作品生产与数据证据账本.md

tools/
  T1-动态对标研究.md
  T2-挑战者与路线发散.md
  T3-高难视觉专项测试.md
```

| 文件 | 负责什么 | 不负责什么 |
|---|---|---|
| `00` | 全局权限、证据、返回关系、停止条件 | 不直接创作作品 |
| `01` | 发散种子、因果去重、形成3—5张承诺卡 | 不写完整故事 |
| `02` | 把唯一冠军承诺发展成完整故事 | 不最终判断是否触发T2 |
| `03` | 独立审查、RETURN路由、T2门控、关键视觉验证 | 不直接重写完整故事 |
| `04` | 分镜蓝图、逐张提示词、实际成图QA | 不改变故事核心因果和结局 |
| `05` | 最终发布文案、发布后事实复盘 | 不用文案修复故事硬伤 |
| `B1` | 周期性市场与受众快照 | 不为单篇直接选题 |
| `B2` | 现实素材卡和叙事功能卡 | 不拼装完整剧情 |
| `B3` | 保存生产事实、发布数据和Prompt改动证据 | 不自动修改工作流 |
| `T1` | 围绕一个市场不确定点研究外部样本 | 不生成选题或故事 |
| `T2` | 生成一条单变量挑战者路线 | 不决定自己是否应该被调用 |
| `T3` | 为1—3个高难视觉场面测试替代调度 | 不写整片分镜 |

# 4｜阶段01：选题发现与承诺候选

## 4.1 谁来运行

主创AI，会话A。

## 4.2 加载哪些文件

```text
core/00-全局原则、证据与权限.md
core/01-选题发现与承诺候选.md
```

按需补充：

- `B1`的一页摘要；
- `B2`中与本轮直接相关的少量资产卡；
- 近期作品高权重指纹；
- 本轮现实素材。

不要默认加载整个B1、B2和全部历史作品。

## 4.3 复制哪个输入块

从`INPUT_TEMPLATE.md`复制：

```text
A5｜直接复制给01的版本
```

你通常只需要填写：

1. 本轮启动方式；
2. 是否修改默认市场风险；
3. 明确不要什么；
4. 是否有必须使用的素材；
5. 特殊制作或安全限制。

## 4.4 01会输出什么

正式输出名称：

```text
《选题发现与承诺候选》
```

主要包含：

- 10—12个原始种子短名单；
- 6—8个因果去重候选；
- 3—5张完整承诺卡；
- 横向差异表；
- AI建议与不确定性；
- 创作者裁决区。

## 4.5 你要做什么

只做一个核心决定：

```text
选择唯一冠军承诺卡
```

同时填写：

- 必须保留什么；
- 明确拒绝什么；
- 是否承担更高市场风险，可空。

## 4.6 交给02什么

只交接：

```text
1. 被选中的完整冠军承诺卡
2. 创作者必须保留的内容
3. 创作者明确拒绝的内容
4. 本篇平台、安全和特殊制作限制
5. 与本篇直接相关的背景卡，可空
```

不要交接：

- 其他未胜出承诺卡；
- 原始种子清单；
- 01全部发散过程；
- 未采用的成熟作品路线。

## 4.7 何时重新运行01

- 03判定`RETURN 01`；
- 02发现承诺卡内部冲突并输出《退回01建议》；
- T2比较后发现必须改变表层事件或用户等待结果才能成立。

返回01时，在A区选择：

```text
D. 我有一个已有方向，但希望重新构造
```

补充03或02的最小返回结论，不要把完整审查过程全部塞回去。

# 5｜阶段02方式A：首次发展冠军故事

## 5.1 谁来运行

主创AI，会话A。可以与01使用同一主创会话，也可以新开主创会话。

若沿用01会话，必须明确：

```text
只发展已经选中的唯一冠军，不再讨论其他候选。
```

## 5.2 加载哪些文件

```text
core/00-全局原则、证据与权限.md
core/02-冠军故事骨架.md
```

并提供：

- 唯一冠军承诺卡；
- 必须保留；
- 明确拒绝；
- 平台、安全与制作限制；
- 与本篇直接相关的背景卡，可空。

## 5.3 复制哪个输入块

从`INPUT_TEMPLATE.md`复制：

```text
B2｜首次运行02的直接提交块
```

## 5.4 02会输出什么

正式输出名称：

```text
《冠军故事骨架》
```

必须包含：

- 承诺锁定复述；
- 故事主形态；
- 人物、规则、物件与空间；
- 5—12个主要状态；
- 中段充分性；
- 完整故事本体；
- 高潮、结果与最后一张；
- 记录方案；
- 视觉风险预告；
- `提交03的独立审查包`；
- `故事锁定卡`。

02可以提示“某个变量可能有争议”，但无权正式判定`POSSIBLE T2`或`TRIGGER T2`。

## 5.5 交给03什么

从02正式输出中提取并交接：

```text
1. 原始冠军承诺卡全文
2. 创作者必须保留
3. 创作者明确拒绝
4. 第7节《完整故事本体》
5. 第13节《故事锁定卡》
6. 平台、安全、成年人物与制作硬边界
7. 当前图像模型、参考图与后期能力
8. 已有人物或环境参考，可空
9. T2裁决锁；首次通常写“未触发”
```

最方便的做法是以02的：

```text
第12节《提交03的独立审查包》
```

作为交接目录，再补上第7节和第13节的完整内容。

## 5.6 不要交给03什么

- 02的思考过程；
- 02对故事是否优秀的评价；
- 02对是否调用T2的意见；
- 其他承诺卡；
- 历史废稿；
- 未写入正式锁定卡的讨论。

## 5.7 02出现《退回01建议》怎么办

停止02，不要让主创AI自行偷换承诺。

把以下内容交回01：

```text
原冠军承诺卡
＋ 02指出的内部冲突
＋ 哪些内容必须保留
＋ 哪些内容允许重构
```

# 6｜阶段03 A1：首次独立审查与T2门控

## 6.1 谁来运行

独立审查AI，会话B。

必须是不同于02的会话。模型可以相同，会话不能相同。

## 6.2 加载哪些文件

```text
core/00-全局原则、证据与权限.md
core/03-致命审查与关键视觉验证.md
```

不要加载02文件本身作为创作指令；只输入02已经产出的锁定结果。

## 6.3 复制哪个输入块

从`INPUT_TEMPLATE.md`复制：

```text
C2｜03独立审查＋模式A直接提交块
```

首次运行属于：

```text
03模式A入口A1｜首次独立审查
```

## 6.4 03先判断什么

顺序不能改变：

```text
1. 冠军承诺本身是否成立
2. 02是否忠实执行承诺
3. 是否存在FATAL
4. 应RETURN 01还是RETURN 02
5. 故事是否已经足够
6. 只有故事基本成立，才扫描高权重分叉
7. 无阻断且无需T2，才设计关键视觉测试
```

FATAL与RETURN永远优先于T2。

## 6.5 03可能输出什么

第一份正式输出：

```text
《独立故事审查与T2门控》
```

最终只能得出一个路由结论：

| 结论 | 含义 | 下一步 |
|---|---|---|
| `PASS` | 故事成立 | 同次调用继续输出关键视觉原型方案 |
| `PASS WITH NOTE` | 有非阻断提醒 | 带提醒继续关键视觉原型方案 |
| `RETURN 01` | 冠军承诺本身需要重构 | 返回01 |
| `RETURN 02` | 承诺成立，但故事骨架需要修改 | 返回02方式A修复 |
| `POSSIBLE T2` | 有潜在分叉，但价值未确定 | 由你决定是否运行T2 |
| `TRIGGER T2` | 有明确高权重分叉 | 默认运行T2，你可否决 |
| `PAUSE` | 材料、成本、模型或安全条件不足 | 补条件或暂停 |

如果结论为`PASS`或`PASS WITH NOTE`，03还会在同一次输出中继续生成：

```text
《关键视觉原型方案》
```

如果是其他结论，03必须停止，不能提前做视觉测试设计。

## 6.6 RETURN 01怎样交接

重新运行01，交接：

```text
1. 原冠军承诺卡
2. 03《独立审查裁决卡》
3. 必须改变的承诺层问题
4. 禁止顺带改变的内容
5. 创作者仍希望保留的核心
```

不要把03整篇长审查全部交回，只交正式裁决卡和必要事实。

## 6.7 RETURN 02怎样交接

回到主创AI，重新运行02方式A，交接：

```text
1. 原冠军承诺卡
2. 原02故事锁定卡与完整故事
3. 03《独立审查裁决卡》
4. “只需要修改什么”
5. “禁止顺带修改什么”
```

要求02：

```text
只修复03指出的故事层问题，不重新选题，不改冠军承诺，
不顺带增加人物、规则、第二高潮或新结尾。
```

02输出新的完整故事后，再以03入口A1重新独立审查。

# 7｜POSSIBLE T2与TRIGGER T2怎么处理

## 7.1 POSSIBLE T2

03认为可能存在分叉，但不确定是否值得多花一次调用。

你只做一个选择：

```text
A. 不运行T2，保留当前冠军
B. 运行T2，正式比较
```

### 选择A

按`INPUT_TEMPLATE.md`的C3写入裁决锁，然后使用：

```text
C5｜原冠军保留或T2原冠军胜出后，返回03继续视觉测试
```

这属于03入口A2。03不得重新触发同一变量。

### 选择B

进入T2阶段。

## 7.2 TRIGGER T2

默认进入T2。你仍可以明确拒绝。

若拒绝：

1. 写明风险承担理由；
2. 把已扫描变量写入T2裁决锁；
3. 使用C5返回03入口A2；
4. 03不得再次触发同一变量。

# 8｜阶段T2：单变量挑战者

## 8.1 谁来运行

挑战者AI，会话C。

可以与03使用同一种模型，但必须再开一个新会话。

## 8.2 加载哪些文件

```text
core/00-全局原则、证据与权限.md
tools/T2-挑战者与路线发散.md
```

## 8.3 复制哪个输入块

从`INPUT_TEMPLATE.md`复制：

```text
T2｜直接提交块
```

## 8.4 交给T2什么

```text
1. 冠军承诺卡
2. 当前冠军故事骨架与完整故事
3. 当前故事锁定卡
4. 03正式门控结论
5. 唯一允许挑战的变量
6. 为什么值得比较
7. 为什么不能融合
8. 不得改变的内容
9. 平台与制作硬边界
10. 已有T2裁决锁，如有
```

不要交给T2：

- 02创作过程；
- 03完整审查过程；
- 03扫描过但未采用的其他分叉；
- “必须证明挑战者更好”之类倾向性要求。

## 8.5 T2会输出什么

正式输出名称：

```text
《单变量挑战者》
```

包含：

- 锁定内容；
- 唯一挑战变量；
- 5—8个挑战者主要状态；
- 中段、高潮与最后一张；
- 挑战者解决什么；
- 挑战者牺牲什么；
- 为什么不能融合；
- 冠军与挑战者比较；
- AI建议；
- 创作者裁决区。

## 8.6 你要做什么

只选择一个：

```text
A. 采用原冠军
B. 采用挑战者
C. 两者都不满意
```

## 8.7 采用原冠军怎样交接

把以下内容写入故事锁定卡：

```text
T2状态：原冠军胜出
已裁决变量：
创作者最终选择：采用原冠军
未胜出方向：T2挑战者
未胜出方向不得融合：是
重新开启条件：出现新事实或创作者明确要求
```

然后使用`INPUT_TEMPLATE.md`中的C5，返回03入口A2。

03只快速确认：

- 原冠军是否被意外改变；
- 是否出现新的FATAL；
- 是否可以进入关键视觉测试。

不得重新开启同一变量。

## 8.8 采用挑战者怎样交接

挑战者目前只是5—8个状态的替代骨架，不能直接进入视觉和分镜阶段。

必须返回02方式B，交接：

```text
1. 原冠军承诺卡
2. 完整《单变量挑战者》
```

# 19｜常见错误与正确处理

## 错误1｜把所有Prompt一次性加载

正确：只加载00、当前模块和上游锁定结果。

## 错误2｜让02自己决定要不要T2

正确：02只负责创作；03独立审查AI拥有门控建议权。

## 错误3｜03发现FATAL后仍然触发T2

正确：FATAL先RETURN 01或RETURN 02。T2不能修复坏掉的冠军故事。

## 错误4｜T2挑战者胜出后直接进入03视觉测试

正确：先返回02方式B，把挑战者骨架发展成完整故事，再进入03 A3。

正确：必须二选一。未胜出方向写入裁决锁，不得拆成零件补回。

## 错误6｜同一个T2变量反复触发

正确：裁决后写入故事锁定卡。没有新事实或你明确要求，不得重开。

## 错误7｜关键视觉失败就淘汰题材

正确：先局部返修、换调度或调用T3；两轮仍失败再返回正确层级。

## 错误8｜04分镜未确认就直接生成全部提示词

正确：04模式A输出后先人工确认，再进入模式B。

## 错误9｜用文案解释图片没有表达出来的核心结果

正确：返回03或04修图。05不能用旁白替代缺失的核心画面。

正确：写入B3，等待4—6篇跨题材证据和反例检查。
