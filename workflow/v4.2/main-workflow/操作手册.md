# V4.2工作流文件使用点、价值与交接手册

## 一、总运行原则

V4.2由两套系统组成：

1. **主体工作流**：负责一篇作品从选题到发布；
2. **独立研究系统**：负责样本研究、来源积累、失败复盘和临时源包生成。

每次只加载：

```text
00_GLOBAL_CONTRACT
＋当前模块
＋上一阶段正式交接对象
＋与当前问题直接相关的少量背景
```

不默认加载：

* 完整外部样本；
* 全部自有作品；
* 比较矩阵；
* 失败史；
* 其他未胜出候选；
* 上游AI的思考过程和废稿。

# 二、正常主链

```text
INPUT_TEMPLATE
→01A创意发现
→01B承诺筛选
→创作者选择唯一冠军
→02故事发展
→03模式A文字审查
→实际关键图测试
→03模式B图片审查
→04视觉生产
→05发布包装
→真实发布
→B3事实复盘
```

各阶段正式交接对象：

```text
01A：
《01A创意空间与来源索引》

01B：
《冠军承诺资产卡2.0》

02：
《冠军故事》
＋《故事锁定卡3.0》

03模式A：
《独立审查裁决卡》
＋关键图测试方案

03模式B：
《实际图片审查》
＋《生产资格卡》

04：
《视觉方案与生产包》
＋实际图片
＋最终图序

05：
《图文对齐与发布包》

B3：
《单篇事实复盘》
```

# 三、主体工作流文件总表

| -------------------------------- | --------------- | --------------------- | ---------------- | ------------- | -------------- |
| `00_README.md`                   | 第一次使用或忘记流程时     | 解释整条主链、研究隔离和返回关系      | 无                | 无单篇输出         | 进入INPUT        |
| `01_MANIFEST.md`                 | 检查缺文件、职责或版本冲突时  | 判断哪个文件对哪类信息拥有最终权威     | 文件结构             | 权威关系          | 按权威文件执行        |
| `02_INPUT_TEMPLATE.md`           | 每个阶段开始前         | 把当前信息整理成可直接提交的指令      | 用户信息、上阶段输出       | 当前阶段提交块       | 交当前模块          |
| `00_GLOBAL_CONTRACT.md`          | 运行所有模块时         | 统一默认值、权限、事件主权、支付和返回关系 | 四轴、人工锁定、硬边界      | 不单独创作         | 始终伴随当前模块       |

| `01B_PROMISE_SELECTION.md`       | 01A完成后          | 找出承重元素并形成冠军资产卡        | 01A完整输出、来源、资源    | 3—5张冠军卡       | 人工选一张交02       |
| `02_STORY_DEVELOPMENT.md`        | 唯一冠军选定后         | 将冠军发展成一条完整故事          | 冠军卡、人工锁定、四轴      | 故事＋锁定卡3.0     | 交03模式A         |
| `03_INDEPENDENT_REVIEW.md`       | 故事完成和关键图生成后     | 独立定位失败层级并发放生产资格       | 故事、锁定卡、实际图片      | 裁决卡或生产资格卡     | 返回对应模块或交04     |
| `04_VISUAL_QUALIFICATION.md`     | 03发放生产资格后       | 完成视觉状态、分镜、生图和成图QA     | 资格卡、故事锁、关键图、参考资产 | 视觉生产包、图片、图序   | 交05            |
| `05_STORYBOARD_RELEASE.md`       | 最终图片完成后         | 保证图文一致并完成发布包装         | 图片、图序、故事锁、04 QA  | 引导词、标题、介绍、标签  | 发布后交B3         |
| `R1_HIGH_POTENTIAL_REPAIR.md`    | 03判定整体故事／视觉失败时  | 保住核心，推翻失败实现           | 双锁、失败实现、03诊断     | 修复包           | 返回03           |
| `B1_MARKET_AUDIENCE.md`          | 每4—6篇或季度更新      | 保存市场与受众证据             | 真实后台数据           | 市场快照和最小摘要     | 少量交01A／01B     |
| `B2_ASSET_SOURCE_INDEX.md`       | 保存来源、候选和暂停资产时   | 主体工作流与研究系统之间的缓冲层      | 来源卡、现实素材、暂停核心    | 可调用压缩卡        | 交T1／01A／01B／R1 |
| `B3_PRODUCTION_REVIEW_LEDGER.md` | 生产中和发布后         | 记录退化发生在哪一阶段           | 全链正式输出和真实数据      | 单篇复盘、改动证据     | 更新B1／B2或未来版本   |
| `T1_REFERENCE_SOURCE_PACK.md`    | 参考主导、指定作品或陌生方向时 | 生成3—6个临时参考来源          | 研究问题、目标作品、F层级    | 临时源包          | 交01A           |
| `T2_STRUCTURAL_DISTANCE.md`      | 03发现一个互斥高权重变量时  | 比较两条最小结构路线            | 当前故事、唯一变量、03门控   | 结构距离比较        | 人工裁决后交02       |
| `T3_VISUAL_KEYFRAME_TEST.md`     | 局部高难画面需要专项测试时   | 测试不同视觉调度              | 视觉事实、旧失败图、模型能力   | 测试方案和实际结果     | 交03模式B或04      |

# 四、各阶段具体交接

## 4.1 INPUT → 01A

加载：

```text
00_GLOBAL_CONTRACT
＋01A_IDEA_DISCOVERY
＋INPUT_TEMPLATE的A区
```

可选增加：

```text
B1的最小摘要
B2中的指定来源卡
T1临时源包
现实／历史／科学材料
```

01A输出必须包含：

* 来源数量计划；
* 10—12个具体事件候选；
* 第一眼不可能关系；
* 用户最初等待；
* 事件在人物到来前的状态；
* 至少一个世界事实增长；
* 一次解释模型变化；
* 可见结果方向；
* 保留未知；
* 来源和F层级。

01A不负责：

* 完整故事；
* 人物成长；
* 情绪闭合；
* 主题总结；
* 高潮分镜；
* 生产替代方案。

---

## 4.2 01A → 01B

加载：

```text
00_GLOBAL_CONTRACT
＋01B_PROMISE_SELECTION
＋01A完整正式输出
＋创作者补充
```

01B重点分析：

* 哪些是可替换外壳；
* 哪些是现实进入接口；
* 哪些构成类型承诺；
* 什么让事件继续发展；
* 哪些视觉关系不能替换；
* 来源作品真正保留了什么；
* 哪些未知必须保留。

01B输出：

```text
3—5张《冠军承诺资产卡2.0》
```

每张卡包括：

```text
来源与改编锁
事件与余量锁
承重元素
当前实现假设
标题与首图诚实
选择提示
```

创作者随后填写：

* 选择唯一冠军；
* 最必须保留；
* 最不能改成；
* 来源保留项；
* 必须保留的未知；
* 主要回报；
* 允许的辅助回报；
* 当前实现允许修改范围。

只把唯一冠军交给02。

---

## 4.3 01B → 02

加载：

```text
00_GLOBAL_CONTRACT
＋02_STORY_DEVELOPMENT
＋唯一冠军卡
＋创作者人工裁决
```

02负责：

* 建立功能预算；
* 选择最适合的故事形态；
* 设计人物进入动机；
* 限制人物因果主权；
* 建立观看问题曲线；
* 建立世界事实曲线；
* 完成解释模型换挡；
* 写完整故事；
* 设计主要状态链；
* 明确高潮和主要结果；
* 填写回报支付表；
* 最后进行寓言诊断；
* 建立最低充分记录方案。

02输出：

```text
《冠军故事》
＋《故事锁定卡3.0》
```

交给03模式A。

---

## 4.4 02 → 03模式A

03建议在新会话中运行。

加载：

```text
00_GLOBAL_CONTRACT
＋03_INDEPENDENT_REVIEW
＋冠军承诺资产卡
＋创作者锁定
＋02正式故事
＋故事锁定卡3.0
```

不要提供：

* 02的思考过程；
* 失败废稿；
* 其他候选；
* 主创AI为自己辩护的文字。

03模式A可能输出：

| 裁决                         | 去向       |
| -------------------------- | -------- |
| `RETURN 01A`               | 创意空间重新发现 |
| `RETURN 01B`               | 重新锁定承重核心 |
| `RETURN 02`                | 02进行局部修复 |
| `STORY REBUILD`            | R1模式A    |
| `VISUAL REBUILD`           | R1模式B    |
| `COUPLED REBUILD`          | R1模式C    |
| `STRUCTURE DISTANCE CHECK` | T2       |
| `LOCAL VISUAL TEST`        | T3       |
| `PAUSE ASSET`              | B2暂停资产   |
| `PASS TO TEST`             | 生成实际关键图  |

03模式A只给测试方案，不发生产资格。

---

## 4.5 03模式A → 实际关键图 → 03模式B

根据测试方案生成2—4张图片：

* 入口图；
* 中段新世界事实图；
* 高潮／结果图；
* 必要时增加连续性压力图。

03模式B加载：

```text
00_GLOBAL_CONTRACT
＋03_INDEPENDENT_REVIEW
＋模式A测试方案
＋实际关键图
＋真实生成过程
＋可选T3结果
```

真实生成过程至少记录：

* 模型和版本；
* 每张轮次；
* 使用的参考资产；
* 失败现象；
* 是否更换调度；
* 后期处理。

只有图片通过时，03模式B才输出：

```text
PRODUCTION QUALIFIED
＋《生产资格卡》
```

之后才能进入04。

---

## 4.6 03模式B → 04

加载：

```text
00_GLOBAL_CONTRACT
＋04_VISUAL_QUALIFICATION
＋生产资格卡
＋最终故事锁定卡3.0
＋通过的关键图和调度
＋人物、物件、空间参考资产
```

04输出：

* 记录语法；
* 人物固定锚点；
* 空间固定锚点；
* 物件固定锚点；
* 故事时间表；
* 视觉状态表；
* 完整分镜蓝图；
* 逐张生图生产包；
* 成图QA；
* 删除记录；
* 最终图序。

04不能：

* 增加新剧情；
* 增加第二高潮；
* 修改主要回报；
* 用桥接图补故事硬伤；
* 用旁白替代未生成的核心画面。

---

## 4.7 04 → 05

加载：

```text
00_GLOBAL_CONTRACT
＋05_STORYBOARD_RELEASE
＋最终实际图片和图序
＋最终故事锁定卡
＋04成图QA
＋平台和语气要求
```

05先建立图文事实表，再完成：

* 逐图引导词；
* 标题候选；
* 推荐标题；
* 剧情介绍；
* 标签；
* 置顶评论；
* 发布一致性检查。

旧故事文字和实际图片冲突时：

```text
实际图片
＋最新人工裁决
```

拥有最高优先级。

发布后，将正式包和真实数据交B3。

# 五、修复和辅助分支

## R1

只有03触发时运行。

```text
故事整体失败 → R1模式A
视觉整体失败 → R1模式B
故事视觉互相拖累 → R1模式C
暂停条件发生变化 → R1模式D
```

R1输出主实现、低成本备用和关键测试预备，完成后必须返回03，不直接进入04。

## T1

在以下情况运行：

* 参考主导；
* 近源改编；
* 指定作品或作者；
* 进入陌生专业领域；
* 01A连续同质；
* B2来源不足。

T1只交给01A：

```text
3—6个临时来源
＋各来源承担的能力
＋F层级
＋保留核心
＋高身份元素
＋不得复制内容
```

## T2

只有一个变量存在真实互斥选择时运行，例如：

* 解释模型；
* 人物因果主权；
* 主要回报；
* 事件范围；
* 来源保留深度；
* 结尾开放程度。

挑战路线胜出后，交02方式C完整化，再回03。

## T3

用于局部高难视觉事实，不用于重写故事。

T3输出不同调度和实际测试结果：

* 生产资格前返回03模式B；
* 04生产中的局部问题可返回04；
* 若涉及主要承诺，仍由03裁决。

# 六、背景文件怎样进入主链

## B1

完整B1不直接交01A，只交最小摘要：

```text
当前入口宽度
市场不确定性
近期高权重避让
尚未验证的问题
平台和生产干扰
```

## B2

01A或01B只读取：

* 本轮指定来源卡；
* 直接相关的现实素材卡；
* 当前暂停资产；
* 少量已验证机制。

不要一次加载全部B2。

## B3

B3接收的是：

* 01A—05正式输出；
* 人工裁决；
* 实际图片；
* 生成事实；
* 发布数据。

B3不自动修改工作流，只记录：

* 来源核心在哪一步漂移；
* 世界陌生度在哪一步下降；
* 主题在哪一步开始主导；
* 人物因果主权在哪一步膨胀；
* 支付层数在哪一步增加；
* 生产预算在哪一步改写核心。

# 七、独立研究系统文件

| 文件                              | 使用价值           | 输入             | 输出／交接             |
| ------------------------------- | -------------- | -------------- | ----------------- |
| `00_RESEARCH_SYSTEM_GUIDE`      | 统一研究纪律、字段和来源索引 | 新样本和研究问题       | 指导其他研究文件维护，不交01A  |
| `01_EXTERNAL_REFERENCE_SAMPLES` | 保存外部作品证据       | 作品剧情和来源        | 被T1少量抽取           |
| `02_INTERNAL_WORK_SAMPLES`      | 保存自有作品与真实数据    | 自有作品、生产和发布事实   | 交比较矩阵、B1、B3       |
| `03_COMPARISON_MATRICES`        | 比较外部与内部差异      | 两类样本卡          | 提炼待验证能力，交T1或工作流研发 |
| `04_TEMPORARY_SOURCE_PACK`      | 规定临时源包生命周期     | 本轮问题和3—6个来源    | 最小摘要交01A          |
| `05_WORKFLOW_FAILURE_HISTORY`   | 防止版本升级重蹈覆辙     | 历史Prompt、作品和复盘 | 交工作流设计，不交创作AI     |

Research中的完整分析结论不直接加入01A。稳定方法已经转译进00和01A；具体样本只有通过T1临时源包才能进入本轮创作。

# 八、最常见的交接错误

| 错误               | 正确做法          |
| ---------------- | ------------- |
| 把全部research交给01A | 用T1抽取3—6个临时来源 |
| 01A直接写完整故事       | 只输出事件核心和增长可能  |
| 把所有冠军卡交02        | 只交唯一冠军        |
| 把02思考过程交03       | 只交正式故事和锁定卡    |
| 故事整体失败却让02小修     | 进入R1          |
| 没有实际图片就进入04      | 先通过03模式B      |
| 04自行改剧情          | 返回02／R1／03    |
| 05用文字补未生成画面      | 以实际图片为准       |
| 一篇数据就修改工作流       | 先进入B3，等待多篇证据  |
| 把失败史当禁止清单        | 失败史只用于工作流设计   |

# 九、一句话记忆

```text
README：告诉你怎么跑
MANIFEST：告诉你谁说了算

00：防止所有模块越权
01A：找到值得看的事件
01B：锁住真正承重的冠军
02：把冠军发展成故事
03：判断哪里失败并发资格
R1：保住核心，推翻失败实现

T2：比较一个结构变量

B1：保存市场证据
B2：保存可调用资产

```
